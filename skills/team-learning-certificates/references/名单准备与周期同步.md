# 终版及领取名单准备

名单准备和成品交付分别验收。经负责人明确授权，可在制证前增量准备终版记录及领取身份行；只写真实姓名、身份、课程、营期、群号和制证明细关联，不写证书附件、正式流水号或“已完成”。这一步不需要成品 manifest；后续正式制作、上传、下载及领取权限仍按 Rules 的原有要求执行。

1. 完整读取当期结营与评优、终版和领取表，并保存全量分页清单。课程参数只取当期课程JSON；当月配置缺失立即停止，不回退历史月份。
2. 只接收已满足结营条件的稳定身份。优秀学习者、优秀队长分别读取明确人工决定和依据；未提供队长名单不等于无人，确认无人后才传空名单。人工名单课程不自动从打卡推断人员：等待真实核准人员补入终版，之后可汇总领取。
3. 终版按“营期＋课程＋稳定身份＋证书角色”查重，一证一行；结课与各优秀角色分别准备。保留已有人工昵称、编号和制作状态；身份、参数或群号冲突列为待处理。
4. 领取按“营期＋课程＋稳定身份”归并，合并制证明细关联，保留既有附件及人工字段。同名且缺稳定键时先核对，不再新增。
5. 执行前重读三表及配置，来源变化则重算；调用共用全流程检查验证完整来源覆盖。只补缺项，保存批次回执并全量回读，再重算验证重复运行零新增。

正式包运行模块为 `runtime/learner/local/publication.mjs` 和 `publish-run.mjs`。由项目提供 `workspace_root`、`base_token`、`roster_table`、`final_table`、`receipt_table`、`course_info`、`output_directory`、`state_directory`，路径合同与打卡本地运行相同。调用 `publishRun({config_file,apply:false})` 预览终版差异，授权后用 `apply:true` 执行；可用 `period`、`course`、`group` 限定已确认范围。领取计划在终版实际ID回读后生成。

周期运行须由用户单独确认频率、时区和自动写入范围；提醒授权不能代替自动执行授权。调度器每次按目标时区计算当前月份，查项目月份登记，再核对课程JSON的营期。CMD仅是稳定启动入口，换期只新增配置登记，不复制脚本，不把课程或Base写死到CMD。迁移设备需重新注册并回读任务动作、触发器和运行账户。

任务只在设备可运行且授权有效时办理；日志区分未配置、登录失败、待核对及写入成功。记录了名单不代表证书可领取，也不代表定时触发已实际验收。
