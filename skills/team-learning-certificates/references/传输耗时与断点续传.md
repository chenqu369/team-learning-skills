# 上传耗时与断点续传

本说明适用于正式包的 `runtime/assistant/scripts/证书附件上传.mjs`。它上传到当前终版指定附件字段，不代办领取表 token 同步、查询页发布或助教清单回写；这些步骤继续按 Skill S9—S13 执行。旧项目的包外上传适配程序不会因更新本包自动获得本次优化，不能假称已经升级。

## 使用方式

在已配置业务材料的项目根目录执行，填写正式包实际路径：

```text
node "<包根>/runtime/assistant/scripts/证书附件上传.mjs" "<制证配置.json>" "<制证人员.json>" "<成品manifest.json>" "<新的预览目录>"
node "<包根>/runtime/assistant/scripts/证书附件上传.mjs" "<制证配置.json>" "<制证人员.json>" "<成品manifest.json>" "<新的执行目录>" --apply --audit "<本次全流程核对输入.json>"
```

配置继续提供 `final_roster_source`、`certificate_ledger_path`、`lark_cli` 及 `attachment_fields.certificate`（真实字段 ID）。若线上列名不是“证书附件”，必须增加 `attachment_fields.certificate_name`，例如项目实际使用的“领取用证书附件”。预览只校验映射和文件，不代表已有附件内容已验收。正式执行前仍须完成当前全量来源对账、编号回写和人工核准。

## 失败后的处理

1. 每张图片上传前读取当前源表，保留全表范围和人工字段不变量检查。
2. 没有附件时只发起一次上传。健康上传不额外逐张下载，批末完整回读验收。
3. 已有单个同名、同大小、有 token 的附件时，通过当前用户授权获取临时下载地址，使用 curl 下载并校验 SHA256；一致才标“复用”。不凭名字和大小认定内容一致。
4. 写请求报错时不自动重传，先重新读取线上；附件已存在且下载哈希正确，标“恢复成功”。没有附件、出现冲突或核对失败则停止并记录待处理。
5. 续跑使用同一正式成品、编号账本和最新来源，生成新的核对输入、使用新的输出目录。不重新制图、重新编号或直接重放旧请求。

Windows 须有 curl.exe。临时下载授权调用最多等30秒；下载连接最多等10秒，传输最多45秒。临时URL不写入回执或错误信息，下载验收临时文件用后删除。上传 CLI 调用最多等120秒；缩短超时不会自动获得重传许可。

## 查看耗时

| 文件 | 内容 |
| --- | --- |
| 传输耗时.ndjson | 每次 CLI、读取目标、上传、下载核验及逐证结果的耗时；过程中持续落盘 |
| 传输汇总.json | 本轮耗时、上传／复用／恢复数量及待处理状态 |
| 上传回执.json | 本轮收到成功回复的上传请求，不含其他批次的历史上传量 |
| 上传验收.json | 批末完整回读通过后的结果；未生成不能称全部完成 |

CLI耗时包含在单张证书耗时中，不能将两者相加。复用需要下载验收，也会消耗时间；本次优化优先减少重复上传、结果不明和排查成本，不承诺固定提速倍数。图片压缩、并发上传及减少必要源表检查未在本次启用。

供项目下载抽样程序复用的函数为 `上传传输.mjs` 导出的 `downloadVerified({attachment, expected_sha256, directory, cli})`；返回实际下载内容的哈希、字节数与耗时，临时文件自动删除。该结果仅证明当前授权用户可下载，不代表学习者权限已验证。
