# 制证与领取规则

制证前的终版与领取名单准备遵循 [名单准备与周期同步](references/名单准备与周期同步.md)：只补真实身份与关联，保留附件、人工字段及既有编号；不能报告成品已完成或可领取。成品 manifest 要求仍用于正式制作与附件交付。

本文件对应 [SKILL.md](SKILL.md) 的 S1—S13（含 S12A 助教清单自动标注），集中维护业务、字段与完成口径。遵守 [共用写作规则](../../Rules/写作规则.md)。原材料、人工核准与正式编号保留；样例和历史验收不作为当前生产输入。

**唯一制作路线：**使用已确认 PPTX 模板和 PPT 脚本填充字段，再由 PowerPoint 导出 PNG 成品；不得用 PNG 底板直绘制证，不生成个人 ZIP。输出图片按 `证书昵称+证书类型.png` 命名。当前实际制作配置和旧 SOP 若仍引用 PNG 底板、旧渲染器或个人包，仅是待迁移材料，不能据此启动新批次正式制作。本轮不改这些运行文件。

## S1 确认来源与当前终版

| 对象   | 来源及规则                                      | 缺失／冲突处理                                 |
| ---- | ------------------------------------------ | --------------------------------------- |
| 资格   | 当期结营规则、完整原始记录及稳定身份核验；优秀取人工选择               | 未核准不正式制作                                |
| 人工终版 | 读取当前 Base 的实际稳定 ID；一证一行                    | 名称含“测试”不等于虚构；不重建覆盖当前表                   |
| 人工例外 | 既有结营核准、人工优秀及依据优先保留                         | 不用新普通 Task 重算删人，不补造历史打卡                 |
| 身份   | 同营期、同课程、经核对的稳定人员标识；保留微信昵称及群号               | 不凭证书昵称合并同名人                             |
| 参数   | 当期课程代码、营期代码／名、日期、角色代码、PPT 模板、字体、版式         | 未知写待确认，不按历史默认推测；renderer 固定为 ppt        |
| 正式账本 | 既有 certificate-ledger.json，test_mode=false | 不新建替代账本；学习者编号、person_id、FINAL-来源标识不是证书号 |
| 版本   | 保存输入快照、源记录 ID、变更与人工确认                      | 源表变化重新导出，不混用两个版本                        |

| 资格核验、制证依据、来源记录ID | 打卡／人工核准证据 | 内部追溯字段 | 保留实际来源 |
| 证书编号 | 正式账本与完成 manifest | 制作前可空；制作后回写文本 | 已有不同值停止，不重编号 |

## S2 生成终版计划

入口为 [learning-cycle.mjs](../../runtime/learner/scripts/learning-cycle.mjs) 的 final-plan；输入结构见 [最终制证标准.json](Sample/最终制证标准.json)。

| 项目 | 规则 |
| --- | --- |
| 行粒度与键 | 一人同营期同课程同证书类型一行；键为营期＋课程＋稳定身份＋角色；群号不用于拆分已确认同人 |
| 资格 | 普通证书核对全部必需 Task；优秀依据人工 excellent_learner／excellent_captain，保留来源 |
| 既有行 | existing_final 已存在则比对；名称或群号差异列 pending；updates 不自动覆盖人工终版 |
| 新增 | 缺行可形成 creates；保留稳定身份、资格与优秀来源；编号留空 |
| 本地推导 | 当前脚本从 period 去掉连字符生成营期编号，从 period_number 生成“第N期组队学习”，从 last_task_deadline 生成中文结营日期，从 course_code 取课程编号 | 
| 推导核准 | 上述只是本地推导值，必须与本次实际制证参数一致再使用；不能把规划截止日自动当成已确认的制证日期 |
| 历史例外 | 新增计划不使历史人工核准失效；保留人工例外并在当前终版单独核对 |
| 完成依据 | 新增、冲突、待确认逐项审查；仅本地 JSON，不代表线上完成 |

### 证书昵称的固定口径

| 情况 | 处理 |
| --- | --- |
| 已有有效人工证书昵称 | 原样保留，不被原微信昵称或新提交覆盖 |
| 证书昵称缺失、null、空字符串，微信昵称有效 | 导出计划可用微信昵称补本地制证名，并保留来源说明；不自动改源表 |
| 证书昵称非空但空格、占位或文件名非法 | 待确认，不把异常非空值当空，不擅自修剪替换 |
| 两个昵称都空或身份不明 | 不进入正式制作 |
| 同身份不同证书角色昵称不同 | 人工确认统一方式，不能擅改人工姓名 |

不同脚本的 name_source 表示法可能不同；这是内部来源说明，不增加人工填写项。上传前仍核对当前源表姓名，不能仅靠补全后的本地输入放行。

## S3 核对并落实终版差异

### 内部终版与领取表

内部“结营与评优”表、“终版证书制作名单”和“学习者证书领取”表分别承担资格与人工评优、逐证制作、逐人汇总领取。稳定表 ID、视图 ID 和字段以当期项目配置及实际回读为准，不套用历史表。

终版按证书类型逐证保存，关联评优来源；领取表关联制证明细并汇总真实附件。工作视图按课程、群号分组。内部简洁领取视图仅用于管理，对学习者交付仍使用 S11 规定的独立查询页。

真实制证只取人工已确认且参数齐全的终版；优秀证书须有明确人工决定与依据。结构测试、名单准备、正式制证、附件上传、查询下载和实际分发分别验收，状态不能互相替代。

负责人审查新增与人工差异后，按本次授权最小写入并回读；保留原记录 ID、人工优秀、例外、昵称和已有编号。已有本次已核准终版时跳过 S2—S3，直接读当前终版，不能再用上游名单覆盖它。

[证书制作表.mjs](../../runtime/assistant/scripts/证书制作表.mjs) 是旧来源整理入口；已有 final_roster_source 时明确拒绝使用。当前终版路线使用 S4，不运行旧脚本重建名单。

## S4 完整导出当前终版

完整来源、范围覆盖与续跑按[全流程防漏与续跑](../../Rules/全流程防漏.md)。每门课程和每个来源记录的每种证书类型均须归类，不能按已有courses配置筛掉缺参数课程。使用当前终版与用户明确增量，不把落款日期当营期；旧快照已含但计划未覆盖也属于遗漏。正式制作用--workflow-audit，包内附件上传实际执行用--audit；包外单次上传/浏览器路线须先手动运行同一共用检查，再逐证完整回读。旧批次的完成记录不证明本轮新增已处理。

运行 [最终证书名单.mjs](../../runtime/assistant/scripts/最终证书名单.mjs)。工作目录必须是助教项目根目录，输出目录必须在该目录内；这是 lark-cli 文件参数约束，不是可随意替换的运行位置。

| 配置字段 | 来源／含义 | 路径或格式 | 缺失处理 |
| --- | --- | --- | --- |
| final_roster_source.base_token、table_id | 本次核对的当前终版 | 稳定 ID | 停止导出 |
| lark_cli | 当前设备可运行的 CLI | 可执行文件名／路径 | 先确认可执行与读取权限 |
| contract_path | 当前资格合同程序 | 相对配置目录或绝对路径 | 保留相应依赖 |
| identity_registry_path | 终版 record_id → stable_id 映射 | 相对配置目录；不同于打卡 registry | 核对既有映射，不能重建抹掉旧身份 |
| certificate_ledger_path | 既有正式账本 | 相对配置目录或绝对路径 | 不用测试账本 |
| normal_role、role_codes | 当期确认角色及编码 | 字符串／对象 | 缺值待确认 |
| deferred_courses | 用户明确暂缓课程 | 数组 | 未明确暂缓不能擅自排除 |
| layout、renderer、ppt | 当期确认的 PPT 模板与导出参数 | 见 S5；renderer 固定为 ppt | 未确认不能进入正式制作 |

| 导出检查 | 接受条件 |
| --- | --- |
| 全量分页 | base／table／record_scope=all_records、每页行数一致；页偏移前进，最终 has_more=false |
| 读取版本 | 分页 rev 一致，来源未变化 |
| 参数 | 同课制证参数唯一、姓名合法、已有编号与正式账本一致 |
| 身份派生 | 优先既有映射或账本；导出可能生成 FINAL-来源标识。这只是来源行映射，不是证书号，也不代替人工解决同人歧义 |
| 输出 | 当前终版-各页.ndjson、制证人员.json、制证配置.json、排除记录.json、飞书终版证书制作单维表.csv、最终来源验收.json |
| 副作用 | 只读线上，不回写编号、制作状态或附件 |

## S5 检查制证输入

| 检查 | 规则 |
| --- | --- |
| 输入 | 使用同一次 S4 导出的人员与配置，不手动拼接两个版本 |
| 模板 | 使用包内 `runtime/learner/assets/certificate-template-v1.pptx` 或负责人确认的同版模板；底图已内嵌于 PPT，不再读取外部 PNG 底板 |
| 版式 | layout 的 name／course／role／date／number 等位置、字号、宽度按实际模板确认；检查字体覆盖与可读性 |
| 课程与角色 | courses[课程名] 内课程编号、营期编号、营期名、结营日期及 role_codes 都明确 |
| 账本 | --ledger 必须是配置指定的既有正式账本；test_mode=false |
| PPT 检查 | --check 校验人员、合同、模板、布局等，不生成正式文件；另核对 ppt.confirmed、provenance、template、font_family 及 Windows PowerPoint 可用；--check 不验证实际 PPT 导出 |
| 实际配置门禁 | 当前运行配置须明确使用已确认的 PPTX 模板和 `renderer=ppt`；旧 PNG 底板或其他渲染路径未改完时停止正式制作 |
| 通过条件 | 身份、姓名、参数、素材、制作方式无缺口；检查日志保存 |

原始 `证书制作/` 代码及素材保留；本包不包含全部真实素材，不能把没有报命令错误当成可正式制作。

## S6 正式制作

使用 [个人证书制作.py](../../runtime/assistant/scripts/个人证书制作.py)，指定新输出目录、同一人员／配置和既有正式账本。程序固定调用 [certificates_ppt.py](../../runtime/learner/scripts/certificates_ppt.py)、非渲染核心 [certificates.py](../../runtime/learner/scripts/certificates.py) 及相邻 PowerShell 导出程序；不接受 PNG 直绘方式。

正式制作会修改本地正式账本；不是普通预览。失败时先保存状态、核对已分配编号和文件再续作，不另起账本重编号。隔离测试须用测试标记、独立账本和独立输出，不能当正式发证。性能测试的渲染方式不覆盖本次用户确认。

制作器不自动回写线上编号／状态，也不自动上传附件。

## S7 验收正式成品

| 对象 | 完成依据 |
| --- | --- |
| manifest | status=complete、test_mode=false，人员、课程、群号、角色、日期与核准输入一致 |
| 编号 | 每证与正式账本同一营期／课程／角色／稳定身份对应；无重复，不把来源 ID 当证书号 |
| PNG | 实际可解码，数量等于本批证书数；每张文件名严格为“证书昵称+证书类型.png”，同名不同身份放在各自稳定身份目录；大小及 SHA-256 可复核 |
| PPT | 核对导出页数与图片数量一致，且模板内字段替换完整；不能只验本地配置 |
| 视觉 | 检查真实样张，尤其长昵称、特殊字符、日期、角色与编号位置；未经检查不报版式通过 |

## S8 回写并回读编号状态

按本次授权，对准确终版 record_id 回写已验收证书编号和实际制作状态；保留无关人工字段和旧附件。逐证及全量回读，核对编号、姓名、身份、角色、日期与正式账本／manifest。

已有不同编号或来源变化时停止。包装程序和单次上传程序都不代办此步；本包没有通用编号回写命令，不能以“制作完成”推断“终版已更新”。

## S9 核对领取身份及关联

| 事项 | 规则 |
| --- | --- |
| 粒度 | 终版一证一行；领取一人同营期同课程一行，汇总该人的全部证书 |
| 身份 | 经确认的 stable_id；同名不同人独立，不凭昵称合人 |
| 目标 | 同一已确认 Base；记录真实领取表 ID，默认业务名称“学习者证书领取”不代替稳定 ID |
| 关联 | 制证明细使用准确终版 record_id；缺行、缺关联先准备并回读，再运行单次上传 |
| 既有内容 | 保留人工字段、历史回执和原附件；不在当前终版的既有条目先核对，不自动删除 |
| 本地 receipt-plan | 输入实际 manifest、匹配的 people 数组、existing_receipts；输出 receipts、creates、updates、pending，仅本地 |
| 两套键 | 本地 receipt_key 与线上归并标识须按实际映射核对，不能直接把本地输出当写表载荷 |

`receipt-plan` 直接读取 manifest 中每张 PNG，核对文件存在性与 SHA-256；不再读取或要求个人 ZIP。

### 领取配置与状态字段

| 字段 | 来源／用途 | 规则 |
| --- | --- | --- |
| delivery.mode | 当期配置 | attachment_tokens；禁止并行旧的领取表重复上传路线 |
| delivery.state_path | 本期配置 | 相对配置文件目录；指向真实领取状态 |
| identity_registry_path | 当前终版行映射 | record_id → {stable_id}，上传前必须全部匹配 |
| certificate_ledger_path | 已验收正式账本 | 单次上传程序直接读该值，推荐绝对路径 |
| 领取批次.manifests | 本批正式 manifest 路径数组 | 单次上传程序直接读取各路径，使用绝对路径；已确认更正批次放后 |
| 状态.base_token、source_table_id、table_id、view_id | 实际回读 | 必须与当前来源、领取表及视图一致 |
| 状态.files | 已核对附件回执 | 保留编号、哈希、大小、token，不清空重建以掩盖旧上传 |

## S10 生成上传同步预览

使用助教项目 `助教评价workflow/scripts/证书单次上传引用.mjs`；需要同目录证书领取汇总.mjs。它不是本包内置能力，跨设备须另行准备。

| 检查 | 要求 |
| --- | --- |
| 执行目录 | 助教项目根目录；上传暂存文件、输出与 CLI 文件参数都在项目内 |
| 来源 | 当前终版全部编号已回写；正式 manifest 与账本、映射、源行身份逐证一致 |
| 目标 | 领取身份行与制证明细完整；现有字段 ID 与脚本实际配置一致 |
| 当前实现 | 程序含已部署目标的附件／备份字段 ID；换 Base 不能只改表名或 table_id。单次读取若仍 has_more=true 会停止，不能宣称已全量读取 |
| 计划 | 不加 --apply；核对单次上传计划.json 中复用、缺失上传、目标及原字段保护 |
| 停止条件 | 来源变化、身份不符、既有未知附件、同类型重复、正式文件不符、目标 ID 不适配 |

旧证书领取汇总.mjs 的直接上传路线不作为当前入口；不能为补行而运行它的旧 apply 后又执行单次上传。

## S11 执行并回读上传同步布局

同一条单次上传命令换新输出目录并加 --apply，一次完成以下子动作；不能按三个动作反复运行发放。

| 子动作 | 规则与回读 |
| --- | --- |
| 上传终版 | PNG 只上传到终版“领取用证书附件”；文件名为“证书昵称+证书类型.png”（两个字段直接拼接）。内容与正式 PNG 哈希相同，不重新渲染；有可核对 token 则复用，仅上传缺失 |
| 保护源数据 | 保留原编号附件、原字段和记录；上传前后核对身份、编号、文件哈希及原字段未变 |
| 同步 token | 从准确关联的终版收集附件 token，写领取表“证书附件”；正式入口是附件类型，不是公式，不再次上传 PNG |
| 同格齐全 | 一人格内包含其实际全部普通与优秀证书；存在一个附件不代表齐全 |
| 字段精简 | 领取表保留实际附件、课程／营期、归并标识和制证明细；历史原附件与上传回执继续可追溯 |
| 状态更新 | 实际 --apply 会更新配置和领取状态文件；执行前保存可追溯版本，不宣称仅改线上附件 |
| 输出 | 检查单次上传回执、按需产生的 token 同步回执、基础验收.json，以及实际全量来源与目标回读；不是每种回执每次都有 |
| 重跑 | 先读台账和当前状态；已齐全批次再次预览／核对，新增上传及同步行数应为 0。没有常驻或定时同步，源附件变更需重新运行 |

### 领取页面固定布局

**学习者入口必须是独立查询页，内部视图不构成交付。** 创建或复用以当期“学习者证书领取”为数据来源的查询页；保留原打卡查询页，不将其改成证书查询。优先使用当前CLI真实支持的能力，无查询页接口时使用已登录浏览器完成配置与发布。输出平台实际生成的 `/share/base/query/…` 链接，不拼造链接，不向学习者交付 `/base/…?table=…&view=…`。

| 学习者查询页项目 | 固定要求 |
| --- | --- |
| 标题 | `xx期组队学习证书领取`；xx来自当期课程JSON的期数，不把85写死成后续期数 |
| 备注 | `输入证书昵称，查询下载证书`，逐字保留 |
| 查询条件 | 只保留“证书昵称”一个字段；移除默认课程、群号等条件，不增加人员编号、微信或其他输入 |
| 查询结果 | 仅证书昵称、证书附件；附件为实际附件，普通与优秀证书同格齐全，不显示全量名单、内部关联与计算字段 |
| 发布与访问 | 仅发布这个查询入口供学习者查询；不以开放原Base权限代替查询页，不顺带扩大原表编辑权限 |
| 验收 | 回读标题、备注、唯一查询字段及结果字段；在发布后的查询页输入真实证书昵称，含双证书样本与无匹配样本，验证附件显示及实际下载；记录账号/角色边界 |
| 交付 | 查询页真实URL、对应Base/table/query定位、配置及查询下载证据；未发布或未验证则明确待办，不能把内部视图当成已交付 |

| 对象 | 规则 | 完成依据 |

## S12 验收下载与访问

完整回读领取表：逐人核对准确来源关联、附件数量、名称、大小、token 与全部证书类型。实际下载抽样 PNG，对照正式 manifest 的文件 SHA-256；包含多证书人员样本。

隐藏列不是访问权限。沿用已有分享设置，用实际领取角色核对打开和下载；未验证学习者访问时仅报告当前账号、字段、布局和下载结果，不报告“所有人可领取”，不主动扩大分享。

## S12A 自动标注助教清单并输出结果

证书制作、上传和领取验收完成后，Agent 在同一次任务中执行本步，并增加一项交付输出《助教清单证书状态回写结果》。人工确认转发到学习群后，再将对应行改为“已发放”。

### 状态含义

| 下拉选项 | 使用条件 | 填写人 |
| --- | --- | --- |
| 未完成 | 本课程群证书尚未全部制作、上传及验收 | Agent 或人工按已核实事实填写；新清单按此值初始化 |
| 已完成 | 本课程群当前核准终版的全部证书已正式制作，编号、终版领取附件、领取关联及同格全部证书已回读，下载与访问验收通过 | Agent 在完成制证交付后自动标注 |
| 已发放 | 已确认领取入口或证书转发到相应学习群 | 人工确认后填写；Agent 保留已有值 |

### 回写步骤

1. 读取当期助教清单工作簿和对应月份工作表。完整读取课程、群号、职责、助教姓名及证书状态列，核对实际数据末行、合并区域和现有下拉选项。课程或群号位于合并区时，按真实合并范围解释所属行，不修改合并结构。
2. 按营期、已核实课程对应关系、群号定位助教行，并记录当前助教姓名及职责。同一课程群的运营、专业助教行全部纳入；不只填写运营行。同名不同课程群分别处理；课程简称、方向或群号有歧义时，不模糊匹配写入。
3. 对照当前核准终版和领取表，逐群确认该群全部证书已完成 S7—S12。增量补制要同时核对该群既有证书；仅本批文件成功、仅有部分附件、空领取结构或没有该群制证记录，都不能将整群标为“已完成”。已确认同人跨群的记录按既有身份及群号映射核对，不自行拆分或漏算。
4. 定位实际证书状态列。业务上称“证书发放”栏；已有“证书制作”栏时沿用该列，不另建或改名。按真实表头定位，不能固定写 Q 列或 S 列。下拉选项包含“未完成、已完成、已发放”；已有其他选项、配色和人工值保留，只补缺少的三项。
5. 对已完成且定位明确的课程群，将对应助教姓名行的空白、“未完成”或原有完成勾选更新为“已完成”；已有“已完成”不重复写，已有“已发放”保留。其他非标准人工状态先列待确认。仅补制部分课程群时，不重置其他群的状态。尚未完成的课程群保持原值并列待办；明确要求初始化或核实后更新为“未完成”时，才写入该值。
6. 使用已核对的电子表格 CLI／工具最小写入状态值及必要下拉配置。回读所有目标单元格和下拉选项，检查行数、助教姓名、课程群与预期一致。保存写前值、写入回执及写后结果。写入失败或回读不符时，报告该群未完成回写，保留已核实的制证结果。

### 必增输出：助教清单证书状态回写结果

| 输出内容 | 必填信息 |
| --- | --- |
| 定位 | 营期、工作簿链接／token、工作表名及 sheet_id、实际状态列名 |
| 逐行结果 | 课程、群号、助教姓名、职责、单元格、原值、目标值、回读值、处理结果（已更新／已完成无需更新／保留已发放／待确认／失败） |
| 完成依据 | 本课程群核准终版范围、正式 manifest、编号及附件回读、领取与下载访问验收的记录位置 |
| 汇总与待办 | 已完成课程群数、实际更新助教行数、保留已发放行数、未完成及无法映射的课程群和具体原因 |

最终回复增加：“助教清单证书状态：已将〈课程群〉对应〈人数〉名助教行标注为‘已完成’，已回读；〈待办〉。”没有实际写入或回读时，按实际阶段报告，不能把本地文档更新写成线上回写完成。

这是 Agent 执行 Skill 时的必做步骤。现有制作器和单次上传程序没有内置此回写，不能声称修改本规则就已部署后台自动化。
