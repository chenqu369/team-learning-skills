# 助教招募规则

本文件是“课程规划 → 课程信息 JSON → 招募项目与岗位 → 进度与导出 → 助教清单 → 将定稿名单回写当期课程规划”的主要规则入口。S1—S8、S9a—S9d、S10 与 [SKILL.md](SKILL.md) 的流程图和处理方式表同号对应；匿名格式见 [Sample](Sample/字段说明.md)，通用写法见[共用写作规则](../../Rules/写作规则.md)。

## 通用边界

1. 课程、Task、营期、日期、人员、平台 ID、证书参数均取**当期材料和当前平台回读**。缺失或冲突统一写“待确认”。
2. 当期明确值优先。若本期已明确给出报名成功提示语、`certificate_scene` 和 `certificate_template_ids`，将 `recruitment.previous_snapshot` 留空。需要继承时才重新读取真实上期项目，只取这三类配置；不得继承旧期数、旧 ID、旧报名、旧状态或旧人员。读取快照保存在本地文件供脚本消费，不必把完整任务 JSON 粘贴到对话中。当前脚本仍读取完整快照；精简读取实现留待脚本统一更新。
3. 固定的[上期招募配置快照 Sample](Sample/上期招募配置快照.json)只示范字段结构，`sample_only=true` 的配置文件不得用于生产。例外是用户确认的[负责人微信二维码](Sample/负责人微信二维码.jpg)：本期未提供新二维码时，这张图片是默认业务来源；提供新图时优先使用新图。选定的图片仍须取得并核对平台可访问 URL，不能把本地路径写入 URL 字段。图片中的展示名不能推作文字微信号或平台负责人 ID。
4. 本地预览、浏览器脚本生成、线上草稿创建、实际发布、文件下载、共享表写入是不同状态，分别给出证据。
5. 每次使用新输出目录，保留原始输入、执行台账和回读。请求结果不明时先回读，不自动重发。

## S1 读取当期课程规划

### 来源顺序

| 顺序  | 来源                  | 用法                                    |
| --- | ------------------- | ------------------------------------- |
| 1   | 课程负责人指定的当期课程规划原文    | 课程事实的首要依据；记录文档 ID、实际版本和字段位置           |
| 2   | 当前打卡材料、当期编号规则或负责人确认 | 仅用于规划原文未承载的精确打卡名、稳定课程键、课程编码等字段；记录独立证据 |
| 3   | Sample／历史快照         | 只看格式或查证历史，不作为本期取值                     |

**当期 JSON 确认后的维护规则：**已确认的 `课程信息.json` 是后续所有步骤的课程事实入口；用户新增确认先修订 JSON 并记录依据，再同步规划文档及派生输出。上表用于首次建立 JSON，不允许旧规划或共享快照覆盖较新的确认值。首次输入须显式报告必要缺口、影响及待确认项，完整读取内嵌表格，不能仅生成 pending 后继续声称规则完整。

新增字段：`graduation_mode` 为 `feishu_tasks`（默认）或 `manual_roster`；后者保留制证参数而不生成飞书结营规则。`required_task_ids` 为负责人明确指定的必需编号子集；未指定时保留原 Task1..N 逻辑。`optional_requirements` 记录选做项目，不加入结营门槛。`start_date/end_date` 为日期级排期，`certificate_date` 为独立确认的制证日期（优先于最后编号 Task 截止日）；不补造具体钟点。人工名单课程没有编号Task不构成结营规则缺漏，但人工名单、核准依据和制证日期仍须后续补齐。

## S2 整理并校验课程 JSON

先按下方字段表整理 `课程信息-输入.json`，再从 **Skill 包根目录**执行：

```powershell
node runtime/shared/course-info.mjs '<课程信息-输入.json>' '<新输出目录>'
```

脚本生成 `课程信息.json`、`助教课程事实.json`、`学习者证书规则.json` 和 `待补清单.json`。输出目录已存在时脚本拒绝覆盖。

规划在本期发生经确认的变更时，在下一次岗位预览、发布或进度核对前重读原文，保留旧输入快照，按真实文档版本更新 `source.revision_id`、发生变化的课程字段及对应 `evidence`；缺口保持“待确认”。用**新输出目录**重跑 S2，回读四份输出并更新 `recruitment.courses_file`。若岗位已发布，改本地 JSON 不能更正线上项目／任务或已有报名；须先比对当前平台回读，按受影响范围单独核对线上变更。

### Task 与输出规则

| 情况 | 脚本处理 | 是否可继续 |
| --- | --- | --- |
| 明确 Task0、Task1… | 保留 Task0；`required_task_ids` 只从 Task1 起 | 编号连续且状态已确认时可生成资格规则 |
| 只给 Task 次数 | 不据此补编号；`task_count` 由实际编号派生 | 不可生成资格规则 |
| Task1、Task3 | 保留原值并诊断缺 Task2 | 待确认，不补造 |
| 含 TaskX | 保留未知值并列 `unknown_task_ids` | 待确认 |
| Task 完整但日期缺失 | Task 资格规则可保留；日期单独待补 | 可继续资格核对，正式制证前补日期 |

`助教课程事实.json` 是脚本派生的兼容输出，不是新增手工输入。招募脚本可直接读取 `课程信息.json` 并在内部转换。`学习者证书规则.json` 只向后续提供课程参数/规则，不修改名单、编号账本或生产 Base。

## S3 查找本期招募项目

| 动作 | 输入 | 操作 | 输出/完成依据 | 停止条件 |
| --- | --- | --- | --- | --- |
| 完整查找项目 | 本期名称、`period_number`、项目类型/类别；`recruitment.project_file` 指向本期 `新建项目.json` | `recruit-project` 生成浏览器稿；在已登录平台运行默认只读的 `window.assistantProjectRun(false)`，通过 `GET /api/v1/admin/projects?page={页码}&page_size={数量}` 读到分页结束 | 唯一匹配的已有草稿，或确认没有匹配项；只有本地生成浏览器稿不算查重 | 同名多项、同名不同身份、分页不完整、身份字段缺失 |

## S4 准备并回读本期项目

已有项目按 ID 定向回读；仅在 S3 确认没有匹配项目时创建草稿。添加平台负责人暂为可选步骤。
平台当前回读用于项目、任务、人员与状态，不反推 S1 规划中的群数或 Task。确需复用的上期配置只取通用文案或证书配置，不补当期事实。

| 动作 | 输入 | 操作 | 输出/完成依据 | 停止条件 |
| --- | --- | --- | --- | --- |
| 创建草稿项目  | 下表创建字段；仅在完整查重确认不存在时 | 已登录平台调用浏览器稿的 `window.assistantProjectRun(true)`，再次查重后 `POST /api/v1/admin/projects` 一次；不发送 `status`，不调用发布接口 | 接口返回真实 ID；仍须下一行定向回读 | 请求结果不明时停止，先重新查列表，不能重发 |
| 定向回读    | 真实 ID                        | `GET /api/v1/admin/projects/{id}`                                  | 名称、类型、类别、期数匹配且状态为 `draft` | ID/身份不符或非草稿             |
| 添加平台负责人（可选） | 本期明确指定且已核对的平台用户 ID | 若指定，使用 `POST /api/v1/admin/projects/{id}/managers`，请求体 `{"user_id":用户ID}` | 指定时回读负责人配置；未指定时记录“跳过”并继续 | 微信号不能当平台用户 ID；人员待确认时跳过，不阻断草稿项目准备 |
| 保存证书配置  | 当前场景、模板 ID 数组                | 更新前后读取项目；以平台当前接口保存 `certificate_scene`、`certificate_template_ids`  | 目标字段回读一致，其他字段保留           | 参数缺失/冲突或无法保留其他字段        |
| 交接项目 ID | 定向回读结果                       | 将 ID 写入本期覆盖配置 `target_project_id`                                  | 后续岗位预览读取同一 ID 和同一课程 JSON  | 只有本地 `新建项目.json`，无线上回读  |

创建字段以当前接口为准；若平台接口已变化，先重新核实，不照抄旧快照。

| 字段 | 当期来源与规则 |
| --- | --- |
| `name` | 本期项目名称；与覆盖配置 `project_name` 一致 |
| `project_type` | 组队学习助教招募为 `assistant` |
| `assistant_category` | 接口值 `team_learning` |
| `assistant_period` | `String(period_number)`；不是 `period` 月份 |
| `description`、`content_markdown`、`cover_image`、`tags` | 当期材料或重新核对的可复用内容；没有依据写待确认/省略可选字段 |
| `contact_qr_image_url` | 本期新二维码优先；未提供新图时用 `Sample/负责人微信二维码.jpg`。填写选定图片实际上传并核对后的平台可访问 URL；不得写本地路径 |
| `github_url` | 本流程不发送 |

添加平台负责人是可选步骤，与报名成功提示语中的 `owner_wechat` 是两个字段。
截图只显示微信展示名 `magicyang` 和二维码，不能据此确认文字微信号；见[负责人微信示例](Sample/负责人微信示例.json)。默认图片只解决“使用哪张二维码”，不自动产生平台图片 URL，也不补齐 `owner_wechat`。若本期没有明确的 `post_submit_content`，脚本需要已核对的 `owner_wechat` 才能生成完整提示语；缺失时只可按 `allow_incomplete=true` 生成待补草稿。负责人、证书配置和 `owner_wechat` 不混入项目创建请求。令牌不得写入 Sample、日志或交付文件。`recruit-project` 无平台适配器时只生成浏览器稿，不把本地输出当成线上创建证明；浏览器稿默认只读，`window.assistantProjectRun(true)` 才可能实际创建，必须保存平台结果并按 ID 回读。

## S5 生成并核对岗位草稿

| 核对项        | 规则                                                          | 完成依据                                | 异常处理                        |
| ---------- | ----------------------------------------------------------- | ----------------------------------- | --------------------------- |
| 课程与项目      | 直接读取同版 `课程信息.json`；使用精确 `target_project_id`                 | 来源文档/版本、期数和项目 ID 在输出中可追踪            | 来源过期、项目非草稿或身份不符时停止          |
| 岗位与名额      | 每课两个岗位；运营=`群数`，专业=`群数×2`                                    | 任务数=`课程数×2`，总名额计算一致                 | 群数未知或名额不符时停止；不从平台反推群数       |

| 成功提示语/证书配置 | 本期明确值优先；没有特殊说明时可复用本次读取且一致的上期值                               | 上期完整分页快照与本期解析配置可追踪                  | 上期岗位文案冲突、快照不完整或本期显式值冲突时停止   |
| 负责人二维码     | 新图优先，否则使用 Sample 的默认图片；把选定图片的已核对平台 URL 填入 `qr_image`，按任务 ID 调专用接口回读，规范化 `/uploads/` 与下载路径后比较 | 每个任务二维码与本期选定图片的 URL 一致 | 无法取得图片 URL 或专用回读不符时停止；列表字段为空不能直接判丢失 |

## S7 读取完整进度并输出固定三列表

进度必须来自本期项目的完整任务 JSON。标准输入至少包含 `expected_project`、`project`、`capture_kind=project_tasks`、`captured_at`、`complete`、`total`、`tasks`；原字段名不同时显式提供 `field_map`。

固定展示表头和顺序如下，只显示明确缺人的岗位：

| 课程 | 岗位 | 招募进度（已招/应招） |
| --- | --- | --- |

规则：

1. 使用课程键+岗位或精确标题匹配，不模糊匹配。
2. `capacity` 必须等于规划名额；`claimed_count` 表示当前有效占用名额，不用累计领取数、已提交数或历史报名数替代。
3. 已释放不计入占用；已领取未提交可能占位，但不能直接进入人员名单。
4. 每次输出读取时间和项目 ID。全部招满时仍保留空表并写明结论。
5. 课程岗位缺失/重复、分页未完、任务 ID 异常、人数未知/超额、名额不符、任务未发布/状态未知、存在未匹配任务时，不得判为全部招满。
6. `recruit-progress` 只处理本地快照并生成浏览器稿；浏览器稿实际运行后才是实时平台读取。

### 报名内容与导出回执的覆盖边界

任务占用人数和招满状态不能证明报名人员、提交状态或表单内容未变。同人数换人、已领取后提交资料等变化，都可能需要重新导出。`fingerprint` 在有完整报名明细时纳入报名内容，不再只比较岗位人数。

如连接程序可完整读取报名明细，在任务快照中附 `applicant_inventory`：`project_id` 为当前项目、`captured_at` 为实际读取时间、`complete:true`、`has_more:false`、`total` 和 `records`。每条 records 含稳定报名 `id`、`task_id`、实际 `status` 及当前人员/表单内容；包含当前有效占用名额的全部记录（包括未提交者），各任务记录数须与 claimed_count 一致，不得用空数组或只读已提交者伪装完整。报名身份或提交内容变化时，旧回执失效。

首次招满仍可触发“导出全部”。缺报名全集证据时，仅证明触发了导出，`roster_coverage_verified:false`，须核对实际Excel。已有导出回执但没有可比对的完整报名内容时，脚本返回 `export_pending` 并提醒重新读取/核对或人工重新导出，不把它标作已复用，也不反复自动点击。上次状态为 attempted/uncertain 时先核对下载现状；只有完整报名内容相同且上次触发明确，才可 `export_skipped:true` 避免重复点击。跳过点击也不代表Excel名单验收通过。

当前浏览器稿只读取任务接口，尚无报名全集接口，保留首次导出功能；再次使用旧回执时按上述边界返回待核对。不得猜测平台API或把任务列表当作报名明细。补报、换人、范围扩大、中断/隔天继续和交接完成前，都应重新核对当前来源与旧导出内容，按变化重跑受影响的进度、导出、清单预览及同步步骤。

## S8 按决定导出并核对报名 Excel

| 动作 | 规则 | 完成依据 | 异常处理 |
| --- | --- | --- | --- |
| 决定是否导出 | 导出不是“全部招满”的必然结果；当期负责人按实际交接需要决定本轮是否导出，未满额时记录原因、项目 ID、读取时间、空缺岗位和决定人 | 有本轮决定记录；无需导出则继续读取进度 | 不得把未满额导出解释成招募完成 |
| 再读进度 | 导出前核对本期项目身份、完整任务分页、人数和异常；区分“有效空缺”与身份/人数/状态异常 | 当前项目 ID、读取时间、进度与决定记录一致 | 项目或进度异常先待确认，不用例外决定绕过核对 |
| 防重复 | 先检查同一项目和进度的回执及下载目录 | 已有同批有效文件则复用并重新核对；结果不明先查下载目录 | 不因脚本返回不明而重复点击 |
| 满额且决定导出 | 当前浏览器稿仅在实时 `all_full=true` 时自动点击唯一可用的“导出全部”按钮 | 回执 `status=triggered`/`button_clicked=true`，随后仍须验文件 | 当前稿一旦读到满额会自动触发；不打算导出时不要执行该稿 |
| 未满额但决定导出 | 当前脚本不支持自动触发；由人在目标项目任务页确认唯一可用按钮并点击“导出全部” | 人工操作记录与下载文件可追溯到本期项目和本轮进度 | 按钮不唯一、不可用或页面项目不符时停止；不得改写 `all_full` 绕过门禁 |
| 核对文件 | 检查原始 `.xlsx` 实际落盘且可打开；核对项目、岗位、审核状态、表单列，并记录仍空缺的岗位 | 保存原名、项目 ID、导出时间和文件哈希/检查结果 | 点击成功但无文件不算完成；不自动重复点击 |

Excel 至少包含“任务名称、审核状态、表单数据”。表单数据保留原始 JSON；缺列或项目不符时停止。

后续脚本若要自动执行“未满额但人工决定导出”，应以独立的导出决定记录为输入：先实时重读并匹配项目 ID、进度指纹和决定范围，确认只有可解释的空缺而无身份/人数/状态异常，再做重复回执检查和一次性点击，最后核对落盘文件。此模式**尚未实现**；当前可自动完成的是人工下载后的 Excel 解析、清单预览、线上表读取与差异核对，不得把文档中的拟议模式当成可用命令。

## S9 填写、回读并交接助教清单

### S9a 预览名单

从已核对的报名原始 Excel 和本期 `课程信息.json` 生成名单计划及 `助教清单_待同步.xlsx`。离线文件不是线上写入凭证；即使共享表暂不可读，也保存原件和待确认项。Excel 的十个岗位检查列为四状态单选：`待核对／已核实完成／存在问题／不适用`，仅供本期清单继续处理，不把样例值当成真实评价。

### S9b 准备当期共享子表

这里的“新建表格”指在**已确认的助教清单工作簿中新增一个子表**，不另建独立工作簿。运行 `roster-sheet-prepare` 前确认 `roster.spreadsheet_token` 和有权限的飞书用户身份。子表显示名由配置的 `period` 提取月份：如 `2026-10` 对应 `10月`；名称只便于人阅读，跨年或同名时仍以工作簿和稳定 `sheet_id` 核对。

| 情况 | 动作 | 完成依据／停止条件 |
| --- | --- | --- |
| 只读预检 | 不带 `--apply`，读取工作簿全部子表并输出是否已有 `N月` | `目标子表.json` 只记录计划；不算建表 |
| 同名已存在 | 先人工确认该子表确属本期，将真实 `sheet_id` 填入本期配置；带 `--apply` 时核对 22 列表头和已有检查状态，只补四状态单选规则 | ID 不符、表头不同、旧值不在四状态中或读取不完整时停止，不覆盖人工值 |
| 同名不存在 | 配置的 `sheet_id` 留空；经本轮确认运行 `--apply`，新建空子表并写入默认 22 列表头及十项单选 | 创建后再次读取工作簿取得唯一 ID，回读表头和单选；请求结果不明先查表，不重复新建 |
| 无权限 | 不执行在线建表或写入，保留 S9a 离线 Excel | 恢复权限后重新读当前工作簿，不用旧快照覆盖 |

十个检查项的单选选项统一为“待核对、已核实完成、存在问题、不适用”，只允许单选。`roster-sheet-prepare` 不填评价结论；S9d 仅给空检查格按岗位补“待核对／不适用”。新填入的适用检查格以浅蓝标运营、浅绿标专业，不适用格浅灰；颜色表示**岗位适用性**，不表示已完成。已有非空状态和人工样式不因名单同步改写。离线 Excel 采用相同的单选和适用色，目标在线表以实际表头、合并区和人工内容为准。

## S10 将招募完成的助教名单回写当期课程规划

### 触发与来源

S9d清单写后核验通过，且负责人已明确本轮名单定稿时执行；满额但未核实人员、下载完成或只有共享表成功响应，均不满足本步骤的输入要求。提前导出或部分定稿只回写明确核准范围，并在总体核对中列出其他空缺或待办，不宣称全期招募完成。

姓名、课程、岗位和群号以本轮平台有效已提交报名与当前已回读助教清单为依据；明确的人工补录、调组及兼任决定须记录独立依据。未报名的手工姓名不能自动视作有效招募结果；没有明确核准时先列待确认。已释放、未提交、空姓名、身份歧义者不填为到岗助教，不能用微信号猜姓名。

课程、群数、当期文档ID及业务规则仍以当前已确认课程JSON为入口。此步骤只同步人员配置，不因修改人员而反向覆盖课程JSON中的Task、排期或制证规则。

### 定位与最小写入

| 项目 | 规则 |
| --- | --- |
| 目标文档 | 从本期JSON的来源标识及项目当期入口确认，不固定某月URL；写前真实读取文档修订号、相关章节和助教块ID |
| 对象键 | 课程稳定键×群号×岗位×平台人员ID或已确认清单身份；姓名只用于显示，不凭同名合并 |
| 岗位映射 | 按当期文档实际标签核对；存在“领航员（运营助教）／航海士（专业助教）”时据此映射，名称不明或角色不匹配先确认 |
| 多群、多专业助教、兼任 | 每个已核准课程群分别列明对应人员，沿用当前展示格式；不按姓名去重而丢失跨课兼任，不以默认人数补人 |
| 可更新范围 | 只更新已核实的对应助教姓名、已确认群号及必要的岗位名单展示，不新增电话、微信号等联系方式到规划 |
| 人工内容 | 原有人员、调组及备注与新输入不一致时列差异并核对依据；无明确替换／撤回决定，不静默清空或覆盖。保留其他负责人、评论、富文本、内嵌表格和附件 |
| 写入工具 | 采用当前飞书文档工具，按最新块ID局部更新。现有roster-sync仅同步助教清单；本步骤没有已验收的通用自动回写命令，不虚构命令或视作程序已自动完成 |
| 幂等与续跑 | 同一对象显示一致时记录复用；部分失败先回读当前文档，只补未生效差异，不重放整篇覆盖。写前版本或人员来源变化则重算 |

每次保存写前规划快照、当前有效人员来源、逐对象差异及授权依据。既有会话授权已涵盖此操作时直接推进已确认范围，不重复请求批准；尚未明确的人员冲突只暂停相应对象。

### 回读与完成判据

3. 保存文档ID、真实写后修订号、章节／块定位、逐项回执和回读结果，确认未改动课程事实及无关人工内容。截图可辅助，不能替代内容回读。
4. 助教项目输出目录为 `output/<本期批次>-招募/规划名单回写-<时间>/`；至少包含写前快照、有效人员来源、回写差异、执行回执、写后回读与未处理项。缺权限时标“规划名单待回写”，不把本地计划或共享表验收当作完成。
5. 将本步骤状态和证据一并交接评价流程。规划回写待办不阻止已核实清单用于评价准备，但必须明确招募交付尚有未完成项。新增报名、撤回、换人和调组后，刷新来源并重新执行本步骤。
