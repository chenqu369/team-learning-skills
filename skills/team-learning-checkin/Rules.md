# 打卡与结营规则

跨批次新鲜度、范围覆盖及续跑按[全流程防漏与续跑](../../Rules/全流程防漏.md)。未知课程必须在pending中列明；graduate输出course_basis_sha256，final-plan要求与当前完整课程信息一致，缺指纹的旧结果须刷新重跑。补打卡、Task变更或人工评优变化后，从受影响输入重算，保留existing_roster中的人工优秀值；不得把“已识别人员处理完”当作原始提交已全部核验。

本文件对应 [SKILL.md](SKILL.md) 的 S1—S10，是本场景的主要业务与字段入口。共用规则见 [写作规则](../../Rules/写作规则.md)。

## S1 确认当期规则与入口

1. 当期已确认的 `课程信息.json` 是规则唯一入口，路径由项目 AGENTS.md 指定。新确认先更新 JSON，再同步规划和派生输出；旧规划、共享参数和历史快照不得反向覆盖。课程、Task、月份和平台 ID 均取当期输入。
2. 首次接收材料，向用户说明必要缺口及影响，不能只把 pending 留在文件中。读取关联排期和嵌入表格，已提取且来源版本未变时复用完整快照。
3. `graduation_mode=feishu_tasks` 按明确的 `required_task_ids` 核验；未明确指定时才沿用 Task1..N 默认规则。明确只需 task3 时，不补造 task1、task2；`optional_requirements` 不加入必需条件。
4. `graduation_mode=manual_roster` 跳过飞书自动结营，graduate 在 `skipped_courses` 列出。不能因没有打卡判未完成，也不能自动认定全员通过。保留课程、编号、营期和制证日期，等待人工核准名单。教学 Task 与旧排期不能变成自动门槛，不伪造打卡证据。
5. `start_date/end_date` 保存日期级确认，不补造钟点。`certificate_date` 用于制证，不能覆盖任务截止；人工名单课程缺制证日期时单列待补。

| 事项 | 规则 | 缺失／变更处理 |
| --- | --- | --- |
| 课程来源 | 使用招募输出的当期课程信息.json；保留规划位置、证据和版本 | 不从历史营期或样例补课程事实 |
| 课程规则 | 优先按明确 required_task_ids；未明确时沿用 Task1..N，Task0 不计默认必需任务 | Task 不明确则对应课程待确认 |
| 平台定位 | 当期 base_token、table_id、表单与视图 ID 取实际读取 | 名称含“测试”不等于虚构或可删除 |
| 规划变更 | 先由负责人确认新规划，更新课程 JSON 及来源／确认状态，保存旧版本；再比较表单和资格差异 | 已产生提交时保留原记录；影响资格、优秀或制证时重新审查，不追溯覆盖人工终版 |
| 适用范围 | 仅处理确认营期；records 中已有营期可能覆盖默认值，运行前必须筛查 | 混期输入阻断，不能指望脚本自动排除 |
| 线上换期 | 先看当前 schema 和数据再决定最小差异 | 旧 new-period-base.mjs 尚不能直接消费标准课程 JSON，不能当作通用换期命令 |

## S2 比较表单字段与选项

| 字段 | 原始来源／含义 | 类型或格式 | 下游用途 | 缺失／冲突处理 |
| --- | --- | --- | --- | --- |
| 微信昵称 | 提交人填写的原昵称 | 非空文本 | 身份核对 | 空值交人工，不用证书昵称替代 |
| 所学课程 | 当期课程信息 | 精确匹配课程名 | 课程规则定位 | 未知课程待确认 |
| 群号 | 当期课程实际群设置 | 原始值保留 | 身份与群冲突核对 | 不推测默认群 |
| 任务名称 | 当期已确认 Task | Task1、task 1 等解析后为 task1 | 任务覆盖 | 非法或未知值待确认 |
| 学习心得 | 原始提交 | 非空 | 有效记录门槛 | 缺项不计有效 |
| 课程评价 | 原始提交 | 非空标量；数值 0 不等于缺失 | 有效记录门槛 | 不擅自改评分 |
| 请填写你对本次课程内容的反馈 | 原始提交 | 非空 | 有效记录门槛 | 缺项不计有效 |
| 证书昵称 | 人工填写，可空 | 非空值须合法、非占位 | 交接证书姓名 | 异常非空值不静默替换 |
| 笔记链接 | 原始提交，可选 | 链接／文本 | 保留证据 | 不增加必需门槛 |
| record_id | 平台记录 ID | 唯一非空文本 | 来源追溯 | 重复／缺失异常 |
| 提交时间 | 平台记录 | 可解析日期时间 | 同任务最新有效记录 | 无法解析异常 |
| 自动编号 | 平台自动编号 | NO. 后接数字 | 原始记录与身份合同 | 缺失／格式错误异常 |
| 人工核对／核对表结果 | 人工处理 | 原值保留 | “无效”记录不计有效 | 不自动覆盖人工判断 |

表单选项按当期课程、群号、Task 准备，先保存差异。保留历史字段、原始提交和已经存在的人工字段，不为缩减页面删除来源列。

## S3 更新并回读表单

仅对已确认差异操作；无差异直接进入 S4。使用实际页面或当前 CLI 时先查看当前能力和参数，不照抄历史命令。写后回读字段名、类型、必填项、所有选项及表单入口，必要时以明确的测试记录验证后清楚标识；未授权不新增线上记录。

本地 graduate／awards 不会完成表单配置，接口响应成功也不代替结构回读。

## S4 准备核对视图

| 视图用途 | 至少能核对什么 | 保护项 |
| --- | --- | --- |
| 原始提交 | 原微信昵称、课程、群号、Task、原记录 ID 与提交时间 | 全部原记录保留 |
| 异常核对 | 身份、群号、必填项、Task 及待处理原因 | 不用隐藏异常代替处理 |
| 结营名单 | 稳定身份、有效任务、缺失任务、资格、证书昵称、人工优秀字段 | 人工昵称、例外及优秀选择保留 |

领取视图的独立目标、附件 token 和固定布局统一见 [制证 Rules S11](../team-learning-certificates/Rules.md#s11-执行并回读上传同步布局)，本文件不维护第二套领取规则。

不另开学习者或助教提交表单。助教在内部“结营与评优”表直接确认优秀学习者、优秀队长，填写评阅人及依据；旧申报原始材料只作历史来源，不自动覆盖当前人工评阅。

### 内部结营与评优表

原始打卡与内部“结营与评优”表分别保存。结营表保留稳定身份、课程、群号、营期、来源打卡、有效／缺失 Task 和系统判定；优秀学习者、优秀队长、评阅人、依据及备注属于人工字段。

表和视图 ID 从当期项目配置读取。内部工作视图按课程、群号分组；通过者视图筛选符合结营要求的记录。结构测试不代表正式名单已生成；真实同步按稳定身份、营期和课程增量更新，仅写系统字段，保留人工评优，写后回读核对。

## S4A 课程 Task 日历

1. 在当期打卡 Base 使用独立课程日历表，每个课程节点一条记录。日历不按学习者复制节点，不新增报名或打卡门槛；人工名单课程也可展示教学日期。
2. 节点采用 `课程信息.json` 中 `calendar_nodes` 的明确日期、时间和来源。`status` 为待确认／有冲突时保留原文，不填写日历日期。Task 缺具体截止日期时，只标已知的开始和结营日期；连起止日期也未知则保留待确认明细。相对“第N天”及旧月份不能自行换算。
3. `03:00` 标在原文截止日，不前移到上一学习日；`24:00` 保留原文标注日，实际截止为次日00:00。时区为北京时间。仅日期的起止节点不补造实际时刻。教学结束日、最后Task截止和制证日期分别保留；不得互相替代。
4. 月视图标题使用课程简称＋节点编号＋截止时间；完整名称、任务内容、原文日期及来源保留在记录详情。最后Task与结营同日可以在输入中合并说明，不重复推断结营要求。可选 Final 仍是可选，展示不等于必需打卡。
5. `节点键=JSON.stringify([period, course_key, node_id])` 跨重跑保持稳定。节点改标题／日期时更新同一记录；不以标题、日期或行号作为身份。发现重复键或无键旧记录时先列出迁移待办，不能直接重建或猜测匹配。未出现在新计划的旧节点仅列待核对，不自动删除。
6. 脚本生成本地差异计划，不自动写 Base。获授权后复用现有表／视图，只提交新增和变化字段，每批最多200条；不修改人工备注。用 UTF-8 JSON 文件及 `--json @文件` 传参，避免 Windows 命令行长度上限；不要使用本次已验证不支持的 `--json -`。
7. 写后全量回读课程日历表，核对行数、分页结束、节点键、日期与时区，并回读 calendar 类型、起止字段、标题字段。首次展示或布局变化时打开浏览器看实际日程；只有工具栏、加载中或白屏不能算效果验收。保持原始打卡和人工评优数据。
8. 默认只读本次相关操作文档，复用版本未变的完整来源快照；输入变化后重算本地计划。控制台只输出数量和异常，完整记录保存在文件。快照复用与增量计算不得绕过[全流程防漏](../../Rules/全流程防漏.md)要求的新鲜度和范围核验。

字段、命令与验收步骤见[课程日历操作](references/课程日历操作.md)。线上历史实例与本批状态保存在项目工作区，不把10月表ID和旧课程写成通用默认值。

## S5 完整读取原始提交

全量导出后核对来源 Base／表 ID、分页终止、行数、读取版本和营期。has_more／truncated 或版本变化未处理时不能宣称完整。Task0、重复提交、无效提交都保留在原始快照，不直接删除。

## S6 核对稳定身份

| 事项 | 规则 |
| --- | --- |
| 作用域 | 同营期、同课程及确认身份；沿用 base＋table＋period＋course 对应登记 |
| 原昵称 | 始终保留微信昵称；空昵称、跨群冲突或身份歧义交人工 |
| 别名／跨群 | 必须有人工确认及来源，按 [身份合同](../../runtime/learner/scripts/learning-record-contract.mjs) 保留；不能只填一个任意开关就视为已解决 |
| 稳定标识 | 不能用 created_by、同显示昵称或手填编号强行合人；不重置 registry 后重新分配旧人员身份 |
| 异常处理 | 保留原记录与原因；明确人员可继续核验，未明确人员不进入正式制证 |

## S7 核验全部必需 Task

执行 [learning-cycle.mjs](../../runtime/learner/scripts/learning-cycle.mjs) 的 graduate。

| 判断 | 固定口径 |
| --- | --- |
| 有效记录 | 满足 S2 必需项、唯一原记录 ID、可解析提交时间及 NO.数字编号；人工标记“无效”的不计 |
| 任务归一 | Task1、task 1 等归为 task1；Task0 不充抵 Task1..N |
| 重复提交 | 同人同课同 Task 只计一次，使用最新有效提交；无效新提交不抹掉有效旧提交 |
| 结营 | 同一人的全部必需 Task 都有效；多余任务不能补缺少的必需任务 |
| 证书昵称 | 已有有效人工名单昵称优先，其次有效记录中的证书昵称，再次原微信昵称；保留来源说明 |
| 名称来源输出 | 当前脚本为“结营名单人工值／证书昵称／微信昵称”，不要求人另填内部标记 |
| 非空异常昵称 | 占位、空格或不合法文件名交人工；不擅自修剪；可已结营但 certificate_ready=false |
| 人工历史例外 | 新核验不会自动保留旧 qualified 值；必须另保留已核准例外和依据，不能据重算结果删人工终版 |

身份、Task 或姓名有变化时，更新输入版本、保存旧输出，换新文件重跑；不覆盖已经确认的生产记录。

## S8 记录人工优秀选择

助教直接确认结营名单的“优秀学习者、优秀队长”，保留评选人及依据；不增加独立结营条件申报环节。

| awards 输入字段 | 来源／格式 | 规则 |
| --- | --- | --- |
| graduates | graduate 的完整结果对象 | 不是文件名，也不是单独 learners 数组 |
| selections | 人工选择数组 | 一项对应唯一 course＋person_id |
| selections[].course、person_id | 当期已核验人员 | 必须唯一匹配且 qualified=true |
| selections[].excellent_learner、excellent_captain | 人工决定的布尔值 | 只更新显式提供的布尔值；未提供保留旧值，不以空值清除 |
| selections[].reviewer、basis、source_record_id | 评选人、依据和来源 | 业务上必须可追溯；脚本不替代人工核实真实性 |

同一选择重复、对象不唯一或资格不符时停止核对。awards 只生成新 JSON，不新建线上申报表，不自动写 Base。

## S9 写回差异并回读

跨Agent移机、配置和提醒的完整合同见[本地运行与手动提醒](references/本地运行与手动提醒.md)。每个项目使用独立真实输入和授权，不复制本机绝对路径、当期Base或身份数据作为默认值。提醒任务只允许弹窗，不能顺带执行同步；首次设置须明确频率、时间及时区，写后读取任务动作与触发器。

1. 现有 `runtime/learner/local/run.mjs --config <本地配置.json> --preview` 直接调用 lark-cli 读取全表并生成差异，获授权后用 `--apply` 增量写回结营表并完整回读；不依赖飞书内置自动工作流。配置、当前JSON、身份登记及人工确认由项目提供，移机先检查 Node.js、lark-cli、授权与路径。
2. 该入口自动运行全流程范围检查并记录每条原始记录的去向。待确认对象保留，已明确对象可最小更新；全范围交付仍列待确认，系统字段同步不代表全员结营已核准。
3. 不更新已有人工证书昵称、优秀字段、评阅人、依据和备注。空身份按真实来源分别核对，不能将全部空标识合成一个人。
4. 写入响应失败不自动重试。下次读取线上现状，复用已写对象并重算差异；运行锁阻止同机重复启动。该入口不制作证书，不默认创建定时任务。

先读取当前线上名单，比较稳定身份、原微信昵称、群号、资格、人工姓名及优秀值。只写已授权、已核对的差异；不重建有人工数据的表，不覆盖人工优秀或历史例外，不拿隐藏列替代资格判断。

learning-cycle 没有通用写回命令。通过当前可用页面／CLI 写后，完整回读全部目标行及来源关联，核对新增／更新数和未变人工字段。不需要线上更新时跳过此步，并在交接中写明“仅本地核验”。
