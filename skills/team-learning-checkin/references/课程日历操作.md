# 制作课程 Task 日历

先把已确认的排期保存到当期课程 JSON，再生成本地计划、写入 Base 和检查页面。日历用来查看课程节点；结营资格仍按 [Rules S1](../Rules.md#s1-确认当期规则与入口)核验，日期处理按 [S4A](../Rules.md#s4a-课程-task-日历)。

## 1. 准备课程 JSON

打开项目 AGENTS.md 指定的当期 `课程信息.json`。每门课可补 `calendar_short_name` 和 `calendar_nodes`，格式见[匿名样例](../Sample/课程日历输入.json)。先核对规划正文、嵌入排期与人工确认；更新 JSON 后派生，不从旧日历反向覆盖新规则。

| 字段 | 填写内容 |
| --- | --- |
| period、courses[].course_key、name | 沿用当期课程输入，节点身份使用课程键 |
| calendar_short_name | 可选的日历简称；完整课程名仍保留 |
| calendar_nodes[].node_id | 课程内稳定且唯一的节点编号，如 task1、final；改日期时不改编号 |
| kind | task_deadline、start、end、other |
| title | 完整任务内容 |
| date、time | date 为 YYYY-MM-DD 或 null；time 为 HH:mm、24:00 或 null；日期未知时不填时间 |
| status | 已确认、待确认、有冲突；仅已确认且有 date 的节点排入日历 |
| source_label、basis | 原文标注及来源位置／版本；缺来源时节点留待确认 |

没有 `calendar_nodes` 时，脚本只使用有依据的 `start_date/end_date`。它不从 `task_ids`、天数或制证日期推导截止日。课程归一化工具保留日历字段；日历命令读取当期权威课程 JSON，不用招募事实、证书规则等缩减后的投影代替。

## 2. 生成本地计划

在 Skill 包根目录执行。输入可用绝对路径，计划放项目 `workflow/output/<新批次>/`，不要把本批材料写进发布包。

```text
node runtime/learner/scripts/course-calendar.mjs "<当期课程信息.json>" "<新日历计划目录>"
```

已有日历时，先全量读取其字段与节点；保存 `has_more=false` 的 manifest。再运行：

```text
node runtime/learner/scripts/course-calendar.mjs "<当期课程信息.json>" "<新日历计划目录>" --existing "<全量日历.ndjson>"
```

查看 `summary.json` 的新增、更新、未变、待确认数。`records.json` 保存所有节点；`pending.json` 列日期和来源缺口；`create-NNN.json/update-NNN.json` 可直接用于批量接口；`retained.json` 列输入中已不存在、但仍保留的旧节点。该命令不访问飞书、不执行删除，也不保存正式完成状态。

旧预览表未含“节点键”时，依据已保存的课程键、原节点编号和写入回执逐条核准映射，补齐后再全量读取。脚本遇无键记录会停止，不把节点标题当成稳定身份。

## 3. 写入 Base

先查表目录，已有目标时复用其稳定 ID。新建时依次使用计划文件；实际参数以当前 CLI `--help` 为准。

```text
lark-cli base +table-create --base-token <本期Base> --name "课程任务日历" --fields @<计划目录>/fields.json --as user
lark-cli base +view-create --base-token <本期Base> --table-id <日历表> --json @<计划目录>/view.json --as user
lark-cli base +view-set-timebar --base-token <本期Base> --table-id <日历表> --view-id <日历视图> --json @<计划目录>/timebar.json --as user
lark-cli base +view-set-visible-fields --base-token <本期Base> --table-id <日历表> --view-id <日历视图> --json @<计划目录>/visible-fields.json --as user
```

表／视图不存在时才创建；保存返回 ID 到本批状态文件。新建后核对字段，随后按文件编号顺序提交非空载荷：

```text
lark-cli base +record-batch-create --base-token <本期Base> --table-id <日历表> --json @<计划目录>/create-001.json --as user
lark-cli base +record-batch-update --base-token <本期Base> --table-id <日历表> --json @<计划目录>/update-001.json --as user
```

中断后先重新读取目标表并生成差异，不能直接重放新增载荷。只更新载荷中的管理字段，人工备注另列保存。无需变更的记录跳过。

## 4. 核对日期和页面

1. 全量读取日历表并检查 manifest 的行数、时区及分页；逐项比较 `节点键`、标题、任务内容、日历标注日、实际截止和来源。重跑差异计划应为新增0、更新0，待确认项仍单独列出。
2. 回读视图及 timebar：type=calendar，start_time=日历标注日期，end_time=日历结束日期，title=节点标题。记录日期级字段用 yyyy-MM-dd，实际截止用 yyyy-MM-dd HH:mm。
3. 打开日历，查看目标月份，核对一个03:00节点、一个24:00节点（如有）及跨月节点。月格较窄时保留课程简称、Task编号和时间，点击查看完整内容；同日折叠条目可展开或切周视图。
4. 页面只显示工具栏时等实际日历主体出现；接口成功不能代替页面验收。按本次授权范围交付链接及待确认项。

## 如何节省时间和 token

| 重复工作 | 本方案 |
| --- | --- |
| 每次重读所有课程原文、人工拼写节点 | 排期一次提取为权威JSON；只对变化或缺口补读来源 |
| 逐条调用接口 | 本地按节点键比较，单批最多200条；无变化不写 |
| 长记录和回执挤入对话 | 完整资料落盘，控制台仅输出数量及错误 |
| 重试时重建表和重放全部记录 | 保存平台ID，续跑先读取目标，再生成新增／更新差异 |
| 每次加载全部业务细则 | SKILL.md 只保留功能与操作入口；具体规则、日历操作按需读取 |

这些是可复用的处理方式，尚无跨批次耗时和token对照测量，不承诺节省比例。
