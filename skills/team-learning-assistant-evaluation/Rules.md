# 助教评价规则

本文件是助教评价的主要规则入口。按 [SKILL.md](SKILL.md) 的 S1—S12 执行；共用要求见 [写作规则](../../Rules/写作规则.md)。仅使用当期材料，不由历史样例补齐人员、日期或等级。

## S1 读取当期清单

| 事项 | 规则／依据 | 缺失或冲突时 |
| --- | --- | --- |
| 来源 | 使用招募交来的当期共享表；核对工作簿 token、子表 ID、月份及完整行数 | 来源不明回招募确认 |
| 快照格式 | 顶层 `headers`、`rows`；读取结果不得 `ok:false`、`has_more:true`、`truncated:true` | 重新完整读取，不用截断快照评价 |
| 必需表头 | 课程名、职责、姓名、微信号、评价打分，各恰好一列；保留其余原表字段 | 缺列或重名停止 |
| 合并单元格 | 课程、群号可按原表向下继承；不能据空单元格删人 | 原表边界不清交人工 |
| 身份键 | `JSON.stringify([课程名, 职责, 微信号])`；平台另核对姓名。群号保留，但不用于掩盖同键重复 | 同键多行停止，由人工决定 |
| 人工字段 | 姓名、微信号、群号、职责、人工调组、观察员、过程字段、备注、检查状态、评价打分、人工结营与优秀信息保留 | 不以新快照覆盖人工差异 |
| 生产输入 | `evaluation.source_snapshot` 指向完整共享表快照；真实运行令 `people_file:null` | people_file 只作演示，不能旁路源表 |

新增助教、人工调组、等级/资格/加成更正、扩大月份或课程范围，以及中断后继续时，先重新读取当期源表全集并生成新预览。人数相同也须比对业务身份键和实际字段；旧预览与旧回执仅用于增量对账，不代表当前名单完整。每个在岗人员都应有任务、证书、鲸币的独立结果或明确待办；空岗位单列，不从范围中消失。准备报告整体完成前，再核对当前全集与处理全集，不能只统计已执行操作。

### 配置与决策字段

所有相对配置路径按配置文件目录解析；CLI 的 `--out` 按执行目录解析。

| 字段路径 | 来源／解释 | 类型／格式 | 使用位置 | 缺失处理 |
| --- | --- | --- | --- | --- |
| `period` | 当期月份 | YYYY-MM 字符串 | 本期上下文 | 待确认；不取样例月份 |
| `output_dir` | 执行人指定新输出位置 | 路径 | 不给 --out 时使用 | 推荐显式 --out |
| `evaluation.source_snapshot` | 当期共享表完整快照 | JSON 路径 | 人员、岗位、等级来源 | 真实评价阻断 |
| `evaluation.people_file` | 演示人员文件 | 生产为 null | 样例路径 | 不作为生产输入 |
| `evaluation.decisions_file` | 负责人补充确认 | JSON 路径 | 资格、S 加成、状态 | 未确认部分挂起 |
| `evaluation.learner_recruitment_date` | 当期学习者招募开始日期 | YYYY-MM-DD 或 null | 证书截止日 | S/A/B 证书待确认 |
| `evaluation.learner_recruitment_node` | 字段约定 | 固定 start | 防止误用其他日期节点 | 不是 start 则不继续 |
| `evaluation.adapter_file` | 本期平台连接程序 | 模块路径或 null | 在线核对／执行 | 无模块仅能本地预览 |
| `decisions[业务身份键].eligible` | 人工奖励资格确认 | true／false | 鲸币资格 | 未知则金额待确认 |
| `decisions[业务身份键].s_bonus` | 人工 S 档加成 | 数值 0.5—1.5 | S 鲸币 | 未确认不猜金额 |
| `decisions[业务身份键].states` | 按职责码记录状态 | 对象，键如 O01、O03 | 检查预览 | 整体替换该人 states，不是局部合并；提交时保留全部已核实状态 |

决策文件不得改姓名、微信号、岗位或等级。等级来自共享表。决策文件的每个业务身份键必须匹配当前源快照；有新增/更名/错键时，脚本在生成预览前拒绝，不能通过只遍历旧人员静默丢掉该条确认。旧 `b_certificate_confirmed` 只为兼容解析，不作为 B 档发证门槛；旧 `next_recruitment_start_date` 不可继续使用。

## S2 核对开营职责

开营与结营检查由观察员共同维护，保留已有非空人工检查项；旧勾选或空白不是完成证明。不适用必须符合岗位分工。状态固定为“待核对、已核实完成、存在问题、不适用”；岗位适用与完成状态分开，不凭颜色判完成。表格颜色沿用招募清单；预览 HTML 的岗位配色也不能替代文字状态。

| 码 | 适用岗位 | 核对事项 | 对应列／证据 |
| --- | --- | --- | --- |
| C01 | 全部 | 培训、测试、加入助教群及学习群 | 学习群；群链接本身不证明全部完成 |
| O01 | 运营 | 欢迎公告、日程与开营文案 | 群欢迎公告 |
| O02 | 运营 | 开营与入群引导 | 开营 |
| P01 | 专业 | 教程预习、实操与环境验证及卡点 | 助教小群；仅有群链接不足 |

适用列默认口径来自 [岗位适用项.json](../../runtime/assistant/assets/岗位适用项.json)。运营负责群欢迎公告、开营、DDL提醒；专业负责答疑、作业评审；开营集中检查、学习完成、结营集中检查、评优、结营为共用项。沿用既有下拉状态与人工值，不把检查项做成自动评分。

## S3 记录实际问题

| 动作 | 保留内容 | 不做什么 |
| --- | --- | --- |
| 记录实际发生的问题 | 人员身份、问题时间、来源、影响、处理人与结果、未解决事项 | 不要求逐课程逐 Task 巡检，不按发言条数评价 |
| 更新已有事项 | 原始证据与后续处理关联 | 不删历史记录，不把“未发现问题”自动变成“已核实完成” |

## S4 核对结营职责

| 码 | 适用岗位 | 核对事项 | 对应列 |
| --- | --- | --- | --- |
| O03 | 运营 | 实际任务内容、截止时间、链接完整 | 群欢迎公告 |
| O04 | 运营 | 按计划提醒 DDL | DDL提醒 |
| O05 | 运营 | 优秀申报名单、链接与专业助教一致 | 评优 |
| O06 | 运营 | 交接结营、优秀名单和待办 | 结营 |
| P02 | 专业 | 答疑与未解决问题交接 | 答疑 |
| P03 | 专业 | 作业评审及反馈覆盖 | 作业评审 |
| P04 | 专业 | 评优依据与运营交接 | 评优 |
| P05 | 专业 | 收尾评审、评优及未解决事项 | 结营 |

O01 与 O03 使用同一展示列但属于不同核对点；状态以职责码分别保留，不能后一次覆盖前一次证据。

## S5 确认人工评价

| 事项 | 规则 |
| --- | --- |
| 等级 | 人工给 S/A/B/C/D；空等级保留待确认，不从完成项数、问题数或发言数计算 |
| 资格 | eligible 单独确认；不由等级替代 |
| S 加成 | 人工确认 0.5—1.5；不能默认取上期或样例值 |
| 历史处理 | C 首次下期禁招、累计两次移出；D 移出，由负责人核对历史后处理，不由本地预览自动执行 |
| 精英贡献次数 | S/A 计入既有“两次评优”条件，B 不计；不把一次 S/A 直接记成两次，累计情况及入团登记由人工核实并留证据 |

## S6 生成本地预览

入口为 [助教评价入口.mjs](../../runtime/assistant/scripts/助教评价入口.mjs) 的 evaluation-preview；计算口径见 [单维表评价.mjs](../../runtime/assistant/scripts/单维表评价.mjs)。

| 检查对象 | 接受条件 | 不符合时 |
| --- | --- | --- |
| 人数与身份 | 与当期快照逐人一致，无空身份或重复键 | 修正来源后重新生成 |
| 检查状态 | 保留已确认状态和证据，未知仍待核对 | 负责人补证据 |
| 证书与鲸币 | 等级、日期、资格及金额分别展示 | 缺项挂起，不强行补齐 |
| 输出 | 评价与发放预览.json、岗位适用项.html、运行摘要.json；applied:false | 仅代表预览，不报已发放 |

脚本的提醒日期输出不是已设置的定时提醒，也不代替当期安排；是否采用需负责人确认。

## S7 回读平台身份与来源

| 条件 | 规则 |
| --- | --- |
| 平台入口 | 贡献者平台 → 助教管理 → 鲸英助教团 → 当期对应项目与助教记录；不得操作其他期或其他项目成员 |
| 连接程序 | adapter_file 导出 `createTransport(config)`；本包未内置实际平台连接程序 |
| 来源读取 | `readSourceInventory()` 不接受旧计划ID过滤，完整分页读取当期全部在岗助教，返回 `{complete:true, has_more:false, total, people:[...]}`。每人含 business_key、姓名、微信号、课程、职责、等级、资格与 S 加成；total 必须等于数组长度，身份集合必须与预览完全相同 |
| 平台读取 | `read(ids)` 返回完整、唯一、正整数 assignment_id，人数及身份逐项匹配 |
| 实际执行 | `--apply` 前必须有新鲜回读（fresh_readback）；任一错配、重复或源表变化停止 |
| 无连接程序 | 可人工核对并留证；不能把本地预览包装成平台执行成功 |

仅支持 `readSource(ids)` 的旧连接程序只能核验已知人员，看不到后补者，不能执行 `--apply`。必须补充全量接口后再执行，不得把过滤后的结果伪装成全集。每次任务/证书/鲸币办理前后都会再次核对源全集；新增、移除、同人数换人、重复或人工确认变化时，立即停止受影响批次，保留已有执行回执并重新预览，只办理尚未完成部分。只读核对若缺全量能力，结果会保留 `scope_pending`；不能据平台既有人员回读成功宣称当期全集已覆盖。

## S8 完成并回读全部任务

先调用 completeTask 完成整批任务，逐条回读，再整批核对；全部任务完成后才允许处理证书。任一失败先查执行台账，不能不核对现状就整批重试。旧的任务完成与发证合并接口不能替代此顺序。

## S9 处理证书决定

| 等级 | 证书决定 | 日期 |
| --- | --- | --- |
| S/A/B | 优秀助教证书；B 不另设确认开关 | 当期学习者招募开始日期加 30 个自然日 |
| C/D | 不发证；保留真实人工等次，不猜平台不支持的等级映射 | 不需补造证书截止日 |
| 未给等级 | 保留待确认 | 不发证、不猜等级 |

截止日不是助教招募截止日，也不是下期招募开始日。日期缺失只挂起需要发证的人员；已核实的任务仍可完成。连接方法为 setGradeAndIssueCertificate／setNoCertificate。

## S10 回读证书结果

核对任务身份、完成状态、人工等级、证书类型和截止日。当前发放程序自动回读任务、等级与证书名称，但没有单独验证截止日的字段比较；截止日须由连接程序补充验证或人工平台回读，不能仅凭程序成功报日期已核实。已一致的证书跳过；已有证书与当前等级、名称冲突，或 C/D、缺等级却已有证书时停止，交人工处理，不自动撤证。接口回执成功不等于回读通过。

## S11 核对并处理鲸币

| 等级 | 运营基础值 | 专业基础值 | 补充条件 |
| --- | --- | --- | --- |
| S | 7 | 5 | 加人工确认的 0.5—1.5 |
| A | 5 | 3 | 无额外默认加成 |
| B | 2.5 | 1.5 | 无额外默认加成 |
| C/D | 0 | 0 | 不发奖励 |

金额单位为鲸币，不自动换算积分。非鲸英助教的奖励资格，按既有“两次评优”与入团规则人工核实，不因 S/A/B 自动视为有资格。已定级且 eligible=false 时为 0，C/D 固定为 0；S/A/B 资格未确认或 S 加成未确认时金额待确认。grantCoins 是独立动作：已有同金额跳过；已有非零但不同金额停止核对，不追加差额、不覆盖。连接程序无此能力时记录 pending_rewards，不阻断已经核实的任务和证书结果。

## S12 交接结果与待办

| 状态 | 必须保留的证据 |
| --- | --- |
| 本地预览完成 | 当期输入、预览、数量与待确认 |
| 平台任务完成 | 实际 assignment_id、逐条和整批回读 |
| 证书处理完成 | 证书决定、日期、平台回读；待发人员单列 pending_certificates |
| 鲸币处理完成 | 资格、加成、金额和回读；未完成单列 pending_rewards |
| 整体交接 | 当前清单、检查证据、人工等级、执行台账、核验结果、待办负责人 |

`source_inventory_verified:true` 只证明本批人员范围与实时源全集一致；`readback:true` 不会自动消除 `pending_certificates`、`pending_rewards` 或 `scope_pending`。应分别报告完成与待办，不能据零新增操作或旧证书已存在推断本期全部完成。

学习者的普通／优秀学习者／优秀队长证书由下游学习者流程处理；不能与本 Skill 的优秀助教证书混用账本或身份键。
