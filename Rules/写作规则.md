# 文档写作规则

本项目采用 ASD-STE100 的主要写作原则。按用户要求，中文文本使用约 80% 的简化写法。完整保留业务条件、平台名称、字段和命令。[官方介绍](https://www.asd-ste100.org/about_STE.html)中的标准面向英语；这里的 80% 是项目写法要求，不是官方评分。

## 文字与格式

1. 使用已有业务名称。同一件事使用同一名称，不为普通操作另造词。

2. 使用短句。一句话说明一个动作或判断。

3. 操作句以“读取、核对、填写、导出、回读”等动作开始。

4. 写明谁在何时操作。负责人和时间放在对应步骤中。

5. 先写条件，再写动作。例如：“全部课程招满后，点击‘导出全部’。”

6. 规则按 `1. 2. 3.` 编号。每条说明一个主要要求，必要的例外和处理办法放在同条。

7. 关键步骤使用表格。每行写一个步骤，包含负责人、输入、输出、操作和规则引用。

8. 总 README 只保留一份关键步骤总表，按开营前、进行中、结营排列。各 SKILL.md 说明本环节的具体操作；详细规则集中放在对应 Rules.md。

9. 字段名称、按钮文字、JSON key 和命令保持原文。技术名称首次出现时说明用途。

10. 写出完成依据，如重新读取的状态、实际下载的文件、证书编号和附件。不能只写“处理完成”。

11. 未知事实列待确认。异常写明停止、重新读取或交人工核对的条件。

12. 不因简化文字而删除身份、来源版本、操作顺序、人工记录、历史例外或检查条件。

13. 补充内容沿用 `explain-clearly` 的教程写法：标题后先说明要做什么，再按实际顺序写谁去哪里操作、使用什么输入、如何检查完成。新增说明与原文使用相同业务名称。

## 业务名称

1. **应招人数**：根据本期课程群数计算的岗位人数。

2. **当前名额**：当前平台任务设置的名额。

3. **已招人数**：平台当前有效占用名额数，不计已释放名额。

4. **招满**：全部课程两个岗位均达到应招人数，且任务、名额和人数已完整核实。

5. **助教清单**：以实际导出 Excel 为人员依据的清单。空缺、未分配和人工调整另行说明。

6. **任务完成**：贡献者平台“鲸英助教团”中的任务状态，不代表证书已发。

7. **评价等次**：当期共享助教清单中人工填写的 S/A/B/C/D。

8. **不发证**：C、D 等次的平台证书选择。

9. **回读**：写入后重新读取平台实际结果。

10. **制作结果文件（manifest）**：证书程序输出的逐证结果，用于核对正式编号、文件和制作状态。
