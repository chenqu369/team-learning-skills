# 全流程防漏与续跑

适用于课程信息、招募、助教清单、评价、打卡结营、评优、制证和领取。完整运行指完整读取、检查和对账；实际写入只处理经确认的缺项。保留原始记录、人工决定、已生成编号和已完成结果。

## 什么时候必须重新检查

本地运行与手动提醒分别记录授权和结果。跨Agent移交时按[本地运行与手动提醒](../skills/team-learning-checkin/references/本地运行与手动提醒.md)检查配置、环境、来源和状态；提醒已创建不表示工作流已运行，任务触发器回读也不表示桌面弹窗已实际送达。不得把提醒任务改为自动同步而沿用原授权。

| 触发 | Agent 的动作 | 向负责人说明 |
| --- | --- | --- |
| 新增、补报、更正、撤回或人工调组 | 刷新该来源，按稳定身份比较新增/修改/移除 | 哪些步骤的旧结果失效；仅有歧义项才提问 |
| 扩大月份、课程、人员或角色范围 | 从新范围的独立来源重新枚举全部对象 | 新增范围有多少对象，哪些尚未处理 |
| 中断后继续、隔天继续、重试失败操作 | 新开运行批次，先读线上当前状态与上次回执 | 已完成、未执行、结果不明分别多少；结果不明不盲目重发 |
| 课程、Task、模板、日期、参数、表结构或业务规则变化 | 从最早受影响的步骤重算，旧结果保留为历史 | 哪些后续结果需复核/重建 |
| 写入、导出交接或准备宣布完成 | 独立来源→计划→执行→回读逐项反向对账 | 未归类、待确认、明确排除以及实际完成的范围 |

Agent 主动做已授权的检查和缺项处理，不把“提醒运行程序”变成重复请求授权。只有缺身份、规则、参数或新增外部动作不在授权内时，带具体差异询问负责人。

## 对账对象与失效范围

| 模块 | 应独立读取的全集 | 对象键与覆盖要求 | 变化后的重跑起点 |
| --- | --- | --- | --- |
| 课程/招募 | 当前规划、课程信息、项目全部岗位和报名明细 | 课程稳定键×岗位；报名用实际领取记录ID。人数相同不能证明人员和提交内容未变 | 课程→草稿→发布→进度→导出→清单，取最早受影响处 |
| 助教评价 | 当期共享清单全员及最新人工决定、平台状态 | 课程/岗位/姓名/微信的既有business_key；未知决定键必须报出 | 清单→决定→任务→证书/鲸币→回读 |
| 打卡/结营 | 当前课程规则、全部原始提交、身份登记及人工评优 | 原始record_id均须进入有效统计或异常清单；不能只核对已经结营者 | 规则/记录→身份→Task→结营→评优→终版 |
| 制证/领取 | 当前终版全表、已确认人工增量、参数、账本、当前领取附件 | 来源记录ID＋角色＋课程＋营期；多选角色展开逐证检查，同名不自动合人 | 终版/参数→制作→上传→领取→下载回读 |

每个来源对象只归入一种去向：计划处理、已完成、已验收复用、明确排除、待确认。计划处理只适用于执行前；待确认和未归类项均不允许宣告该范围全部完成。明确排除要保留负责人的依据，不可把缺参数、程序不支持或不在旧配置中的对象自动排除。

课程层和人员/证书层分别对账。若本批只处理一部分，先以明确范围构建独立来源文件，其余对象在总范围检查中列为明确排除或待确认；禁止先按已有课程配置过滤名单，再用过滤后的计划验证自身。

## 共用脚本

在含 `runtime/` 的 Skill 包根目录执行，Node.js ≥20，无额外依赖：

```text
node runtime/shared/workflow-audit.mjs check <全流程核对输入.json> <新核对报告.json>
```

退出码0表示本轮覆盖/来源检查通过，2表示有缺口。报告列出 missing、unknown、duplicates、changed_sources、invalidated_stages 和提醒。它只核对本地保存的来源及证据，不会替你访问飞书或贡献者平台；运行之前必须实际刷新线上来源。`captured_at` 必须是实际读取或人工确认时间，不能为旧文件补写新时间。

输入结构如下，示意路径、哈希、时间、ID须替换为本批实际值：

```json
{
  "schema_version": 1,
  "workflow": "certificates",
  "phase": "preflight",
  "run_started_at": "本轮开始时间，ISO8601含时区",
  "max_snapshot_age_seconds": 900,
  "sources": [
    {
      "id": "终版名单",
      "kind": "base",
      "stage": "final-roster",
      "used": {
        "path": "准备计划时的终版.ndjson",
        "sha256": "当时固定保存的文件SHA256小写",
        "manifest": "准备计划时的终版.manifest.json"
      },
      "current": {
        "path": "执行前重新读取的终版.ndjson",
        "captured_at": "本轮真实读取时间，ISO8601含时区",
        "manifest": "执行前重新读取的终版.manifest.json"
      }
    }
  ],
  "coverage": {
    "expected": {
      "path": "执行前重新读取的终版.ndjson",
      "key_fields": ["record_id", "证书类型"]
    },
    "actual": [
      {
        "path": "制证人员.json",
        "key_fields": ["最终名单记录ID", "证书类型"],
        "status": "planned"
      }
    ]
  }
}
```

- 所有路径相对核对输入JSON所在目录。`workflow` 为 recruitment/evaluation/checkin/certificates；`phase` 为 preflight/complete。
- `sources` 不只放名单：课程规则、参数、模板、执行配置、制证人员、manifest及所用身份映射也作为输入依赖登记。一般文件用 `kind:file`；平台读取用 platform；负责人直接给的明确名单用 manual。file只校验文件，不能替代线上来源。Base全量manifest须包含同一base/table、rev、行数、all_records和has_more=false。
- `used.sha256` 是制备当前计划时保存的值。来源变更后先输出差异、重算计划，再为新批次建立新的使用基准；不可单改哈希来消除提醒。当前来源应在本轮开始后读取，默认15分钟窗口可按实际批次设置正数秒值，续跑不得沿用旧开始时间。
- `coverage.expected.path` 必须直接引用一个current来源文件。JSON对象用 `array_path` 指定数组，例如 `courses`、`learners`、`final_roster_approvals`；NDJSON直接逐行读取。`key_fields` 按位置对应，各字段支持点路径；数组值自动展开，不能省掉多选证书类型。
- actual可有多个文件，各自指定相同维度的键。`status` 为 planned/completed/reused/excluded/pending。excluded需reason；completed/reused需实际验收回执的evidence_file，不能用本地计划替代。共用脚本只检查证据文件存在并记录哈希，字段内容、下载哈希和角色访问仍由模块验收脚本/实际操作验证。
- 脚本返回ready不等于线上已执行。complete阶段仅允许已完成、已验收复用和有依据的明确排除；必须同时满足各模块的实际验收条件。

## 已接入的入口与旧批次迁移

终版及领取名单准备运行器 `runtime/learner/local/publish-run.mjs` 在实际写入前重新读取结营与评优、终版和领取全表，比较来源及配置，自动保存并执行共用核对输入。只准备身份行和制证明细，不代替正式制证、附件上传、下载与角色权限验收；业务合同见 [名单准备与周期同步](../skills/team-learning-certificates/references/名单准备与周期同步.md)。

| 入口 | 行为 |
| --- | --- |
| 助教评价入口.mjs 的实际 `--apply` 操作 | 必须补 `--audit <核对输入JSON>`，运行时重新核对；执行配置文件也须在sources登记 |
| 个人证书制作.py 正式制作 | 必须补 `--workflow-audit <核对输入JSON>`；制证人员和配置文件须纳入sources或actual。测试fixture免此生产检查；单独--check未带audit仅证明参数可用 |
| 证书附件上传.mjs `--apply` | 必须补 `--audit <核对输入JSON>`；配置、人员和manifest须纳入本批核对，人员必须参与actual覆盖；首次线上全源须与同Base/table审计快照及rev一致，执行中继续核对源全集变化 |
| learning-cycle.mjs 四个本地计划命令 | 可补 `--audit <核对输入JSON>`；整个执行输入文件须纳入sources。未带时明确输出未核验完整范围，不得当成线上完成 |
| 飞书页面、独立lark-cli、浏览器稿及包外上传脚本 | 无法由本包强制拦截；Agent须先运行本共用检查，实际写后再按模块全量回读 |

旧结营结果缺 `course_basis_sha256` 时必须用完整输入重跑graduate再运行final-plan；人工优秀值通过existing_roster保留。评价旧适配器只支持readSource(ids)时不能正式办理，须实现Rules中的readSourceInventory()全量合同。禁止通过删掉新检查来继续使用旧数据。

## 完成时的固定说明

说明本批范围、当前来源版本与采集时间、对象总数及各去向数量、实际写入/复用数量、完整回读和下载/截图证据、待确认及明确排除项。任何来源新增或范围变化后，之前的“全部完成”仅属于旧批次；先重新检查差集，再处理缺项。
