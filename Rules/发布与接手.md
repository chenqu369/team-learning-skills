# 发布与接手

本文件说明完整包怎样分享、项目材料怎样配置，以及换设备或换 Agent 时检查什么。首次使用先读[主 README](../README.md)，实际任务按对应模块操作。

## 目录和材料

1. 只打包 `team-learning-skills/`，包含唯一主 README、四个 `skills/` 模块、共用 `Rules/`、`runtime/` 及 `tests/`。上一级 `组队学习/` 是本地阅读工作区，`.obsidian/`、`欢迎.md` 和本地笔记不随包交付。运行代码内部的 README 属于技术说明，不另作项目主入口。
2. 命令的包根目录是含 `skills/`、`runtime/` 的 `team-learning-skills/`。包可放在任意实际目录；不能把历史工作区位置当成跨设备固定路径。安装到 Agent 的全局发现目录时另按该设备生效的 AGENTS.md 和安装约定处理，保留共用运行依赖。
3. 真实材料与通用包分开保存。项目可使用 `workflow/input/<本期>/` 保存完整来源、`workflow/output/<新批次>/` 保存预览和回读、`workflow/state/` 保存身份及编号状态；已有项目沿用其实际配置，不为套目录搬动正式账本。
4. 当期确认的课程 JSON 是课程事实入口，具体文件由目标项目指定。人员终版、人工评优、身份别名和例外分别保留原始来源。变更、续跑和交付前执行[全流程防漏](全流程防漏.md)，不从历史批次反向覆盖确认值。
5. Sample 用于说明格式，不把其中课程、日期、人员和平台 ID 用于生产。招募 Sample 中的负责人微信二维码是已确认的默认业务图片；它属于有意保留的业务素材，使用和替换按[招募规则](../skills/team-learning-recruitment/Rules.md)。
6. 发布包不加入真实人员导出、运行日志、账号密码、令牌、虚拟环境、node_modules 或Python缓存。现有 Obsidian 配置与人工笔记先保留，不以“重复”为由覆盖或删除。发布检查和本批清单放项目输出目录，不放回通用包。

## 本地阅读与打包

1. 本地继续用 Obsidian 打开 `组队学习/`，欢迎页只链接包内 README 和各模块，不复制业务正文。其他阅读器可以直接打开包内 Markdown。
2. 编辑包内原文件作为唯一正文来源；无需另建阅读副本、同步目录或符号链接。发布包的必要链接使用普通 Markdown 相对路径，不依赖 Obsidian 专用链接、插件或外层欢迎页。
3. 从内层 `team-learning-skills/` 生成压缩包，压缩包保存到项目输出目录。排除缓存、依赖安装目录、本机配置、凭据及真实业务数据；保留必要模板和明确批准的样例素材。不能仅依靠 `.gitignore` 判断压缩包是否干净。
4. 按实际打包文件清单检查包内相对链接、导入和资源是否齐全，必要依赖不能指向外层文件或本机绝对路径。业务配置中的真实路径由接收项目另行提供；包外平台适配程序继续按环境说明交接，不宣称已包含在包内。
5. 接收者解压后从 README 开始，按任务准备运行环境和授权；阅读器自行选择，不要求 Obsidian，也不要求预先安装为全局 Skill。

## 首次接手

1. 读取目标项目 AGENTS.md、主 README 和本次模块的 SKILL.md，定位营期、输入文件、正式平台入口及当前交接状态。
2. 按任务检查 Node.js、Python、PowerPoint、lark-cli 或浏览器工具。脚本相对导入依赖包内目录结构；本地结营入口的路径配置见[本地运行](../skills/team-learning-checkin/references/本地运行与手动提醒.md)。其他命令按各自配置合同解析路径，不统一假设相对于同一目录。
3. 平台登录与授权在目标设备单独核对。需要助教评价平台连接程序或领取上传适配时，由项目另行提供并核对目标字段；不能把缺少适配的本地预览称为平台办理完成。
4. 先生成预览，列出缺口。实际操作按用户授权范围执行并回读；本地计算、正式制证、线上上传、可领取与实际分发分别交付。提醒只提示人工运行，不等于获准自动同步。
5. 交接输入版本、批次目录、实际写入和复用数量、持久状态及待办。人工昵称、优秀选择、核准结果和正式编号按模块合同保留，不能换成空状态重新开始。

## 维护检查

1. 修改主 README 的功能与导航，修改各模块的操作说明，修改对应 Rules 的条件与例外；同一业务规则只维护一个主要入口，其他位置链接引用。
2. 新增文档、脚本或模板后检查相对链接、静态导入和资源路径；包内依赖能从完整包定位。项目另行提供的程序在环境说明中列明，不伪装成包内能力。
3. 纯文档修改核对链接和目录即可。运行代码变化时执行与改动相关的已有检查；发布文件清单及 SHA256 保存在本批输出目录。
